## Project

Headless Python Instagram publisher for a creative data and tech account. Five pillars (tech-explainer, cool-stats, history-timeline, tech-versus, myth-vs-fact) produce animated SVG Reels: Bedrock writes a validated, number-grounded scene, `src/media` draws it as a 1080x1920 SMIL SVG, headless Chrome and ffmpeg render it to MP4, and Cloudinary plus Composio publish it. The carousel, single-image and Luma Reel code paths remain supported formats, but no configured pillar uses them. Posts go out on the workflow's schedule (the day's planned slots) and on demand ("create one", below); the schedule was off from 2026-10-24 to 2026-10-27, and no post went out in that gap. See README.md and docs/operations.md for current behavior; older docs/plans and CHANGELOG entries are historical.

## Validation

- `uv sync --frozen`
- `uv run --frozen ruff check src tests scripts`
- `uv run --frozen ruff format --check src tests scripts`
- `uv run --frozen pytest --cov=src --cov-branch`
- `uv run --frozen python scripts/fetch_voice_model.py` fetches the Kokoro narration model into the gitignored `assets/voice/`; with it, the sample render below narrates each sample. `scripts/narrate.py` is a PEP 723 script locked in `scripts/narrate.py.lock` (`uv lock --script scripts/narrate.py` after changing its dependencies) and runs on Python 3.13.
- `uv run --frozen python scripts/render_svg_reel_sample.py` renders one sample Reel per pillar and a cover still of every sample in every look into `output/svg-reel-sample/` with real Chrome and ffmpeg (no credentials, no network); music is baked in when `uv run --frozen python scripts/fetch_audio_catalog.py` has fetched the library. CI uploads the result as the `svg-reel-sample` artifact.
- The svg-forge validator (`skills/animated-svg/scripts/validate_svg.py FILE --strict-contrast --theme dark` in the svg-forge plugin) must report 0 errors for every sample SVG in every look.
- `uv run --frozen python -m src.main --dry-run` is paid local generation, never upload/publication/history mutation.
- `python -m src.main` is a live publishing command, not a test.

Tests use dummy credentials, disable dotenv, and block sockets. CI exercises Python 3.12 and 3.14 and enforces failures.

## Boundaries

- `adapters/`: low-level service calls.
- `content/`: category-relevant evidence, topic selection, validated content, SVG scenes (`scenes.py`) and number grounding (`grounding.py`). Preserve the legacy string topic wrapper; the orchestrator uses `generate_topic_brief` and passes its sources into captions.
- `media/`: asset generation, JPEG normalization, S3 retrieval, audio, narration (`narration.py`, the Kokoro voice-over, and `audio_bake.mix`), SVG composition (`svg_kit.py` type and clock, `svg_parts.py` framing, `svg_look.py` looks, `svg_depth.py` the moving floor and cubes behind every scene, `svg_solid.py` coin tiles, the extruded number and bar faces, `lucide/` vendored icons, `reel_svg*.py` layouts, with the stat charts in `reel_svg_charts.py`), Chrome and ffmpeg rendering (`svg_video.py`) and ffprobe checks (`reel_probe.py`).
- `slot_rules.py`: forced pillars, on-demand posting refusals and slot times already used.
- `flows/`: compose media and publication; return a confirmed media ID or None for a dry-run.
- `publishing/`: Composio schemas, draft readiness, alt text, final publish callback.
- `state/`: conditional local/GitHub persistence, ownership leases, migration, and receipt transitions.

## Contracts that must survive changes

1. Never make an irreversible publication before `before_publish(container_id)` returns. That callback must persist the publishing state. A callback exception aborts publication.
2. Never blindly retry the final publish call. After its boundary, an ambiguous response requires reconciliation, not a fallback or regenerated post.
3. Do not downgrade confirmed media success because optional audio-history saving failed.
4. At most one slot per run; a run comes from a scheduler tick (a planned slot that is due) or on demand (contract 21). Keep the schedule; on demand adds posts, it does not replace them (from 2026-10-24 to 2026-10-27 the workflow had no schedule and nothing posted). Enforce actual successful-post spacing and the daily cap through shared state. No multi-hour runner sleeps.
5. GitHub Actions must use the GitHub state backend, not ephemeral local state. The dedicated state branch is not an application deployment branch.
6. Atomic JSON replacement alone is not interprocess protection: keep local file locking and GitHub revision compare-and-swap checks.
7. Photo formats (carousel, image, Luma Reel): content responses require exactly five prompts and aligned alt texts before image work. Preserve source metadata from adapters rather than accepting model-authored source URLs.
8. Photo formats: diffusion exclusions belong in `negative_prompt`. Retain the anti-illustration/CGI/typography guards and randomized seeds.
9. Photo formats: all published images are validated RGB 1080x1350 JPEGs below 8 MB. Validate actual delivered bytes; a trusted hostname alone does not prove compatibility.
10. Carousels: filtered-slide removal must keep alt texts aligned. Dry-run must fail when fewer than two carousel slides survive.
11. Bedrock uses bearer-token requests. Botocore is exclusively for authenticated S3 retrieval, not a replacement for Bedrock authentication.
12. Reels (Luma and SVG): missing licensed local audio must be detected before paid video generation or rendering. Preserve required attribution; never mutate audio history in dry-run.
13. Topic attempts and confirmed publications are different records. Preserve legacy history and unresolved receipts. Do not invent media IDs during migration.
14. Keep `uv.lock` authoritative; `requirements.txt` is a generated runtime-only export. Never disable failing tests or hide their exit status.
15. SVG Reels: every number, percentage, date and number word in a scene, and in its caption outside links and hashtags, must appear in the title or excerpt text the adapters returned for that topic (stat scenes: the cited `source_index` record only), after normalizing thousands separators and units. Two repair calls for a scene; then, when only the caption still cites an unsupported number, `grounding.verified_caption` drops the sentences holding it (removing, never adding); otherwise the attempt fails before rendering and contract 19's chain moves on. Never publish an invented, computed or remembered statistic. Source names shown on screen and in the caption come from adapter metadata, never from model text. Scene and caption text describes the subject, never the evidence: `content/voice.py` rejects summary, article, headline, excerpt and "omits / not stated" phrasing the same way.
16. SVG Reels: all text stays inside the Reels safe area (x 60-1020, y 250-1600, with the rise margin) at the minimum sizes of the type scale in `svg_kit.py` (lowered on the owner's ask 2026-10-18): hook 68 px bold, step labels 44 px, details 32 px, takeaway 42 px, and no text under 32 px, also at the peak of any scale pop; the progress bar and the end card stay inside it too. Fit text with the measured width table in `svg_kit.py` (widest of DejaVu Sans, Liberation Sans and Segoe UI); a scene that does not fit raises `LayoutError` before rendering (`compose` first drops the kicker, then the icons). Shapes may turn (card hinges and flips, the ring's tilt, the floor's zoom), but text is never scaled below full size or squashed.
17. SVG Reels: text at least 4.5:1 and marks at least 3:1 on what they sit on, in every look and also at the `DIM` opacity of finished rows (`Look.text_on` and `Look.mark_on` in `svg_look.py`); SMIL only, self-contained (no scripts, external fonts or images; the only `url()` is the internal `#kr-wash` gradient), ids prefixed `kr-`, model text escaped, the hook readable on the first frame (its entrance only brightens and pops it). Every animation runs on the Reel's one clock except the depth layer's loops (`svg_depth.py`), which start at 0, run linear and cover the whole Reel; the depth layer, tile bases and bar faces are decoration below 50% opacity, and the extruded number uses the checked `accent_text`. Never add prefers-reduced-motion gating.
18. SVG Reels: render before publish. The renderer refuses blank frames, and the delivered MP4 must pass `reel_probe.verify` (H.264 High, yuv420p, 1080x1920, 30 fps, expected duration, at most 100 MB, an AAC stream exactly when audio was baked) before any upload.
19. A post is a must (owner, 2026-10-24): a failure before the publisher boundary fails only that attempt, and the run moves on through `post_attempts.attempt_pillars` (the same pillar with a fresh topic, then `tech-versus`, then `tech-explainer`), claiming each slot key again so the cap, gap, window and per-key attempt budget hold. Only a receipt back at `failed` moves on; an `uncertain` one (it reached the publish checkpoint) stops the chain. SVG Reels never fall back to a photo carousel or a Luma video.
20. SVG Reel dry-run renders locally and saves `01.mp4`, `reel.svg` and `scene.json` under `output/dry-run/`; it never uploads, publishes, or writes topic, audio or publication history.
21. `--post-now` (with `--pillar`) is the only exception to the due-slot rule in contract 4, and it is how "create one" (below) posts: the current minute becomes the one candidate slot for that run. It still runs once, inside the posting window, through the ledger claim, daily cap, minimum gap, `before_publish` checkpoint and no-retry rule, and it refuses with a reason when any of them would be broken. `--pillar` alone only swaps the pillar of a slot that is already due.
22. SVG Reel icons come only from the vendored Lucide set in `src/media/lucide/` (ISC; keep its LICENSE beside it and vendor icons unchanged). The scene schema accepts only those names, optional per step, milestone and stat headline; an unknown name is a validation error that gets the one repair call. Icons are stroke-only in the look's accent (3:1), at least 96 px in steps, and their names are never scene text for grounding.
23. Music comes only from `assets/audio/catalog.json` (Mixkit Stock Music Free License: social media video posts, no attribution). The audio files and the generated `catalog_manifest.json` are fetched at run time with a sha256 check and never committed (public repository); never register the tracks with a rights-management service, remix them into music-only tracks or redistribute the files. A failed download never fails a run; `ALLOW_SILENT_REELS` decides whether the Reel may go out silent. The baked fade ends at the Reel's real fractional duration.
24. The Reel container sends `thumb_offset` in integer milliseconds from the composer's `Reel.cover` (the final hold plus 0.5 s, before the 2-second end card), so the grid shows the complete scene. Keep `INSTAGRAM_CREATE_MEDIA_CONTAINER` until the replacement tool's `%23` hashtag encoding is verified against a live caption; it has no `audio_name` field, so none is sent.
25. Cadence for the small account: at most 2 posts per UTC day, at least 180 minutes apart, `post_probability` with one entry per possible count (0 to 2), inside the 04:00-20:00 UTC window. Raising it is an owner decision, not a tuning knob. `post_probability` shapes the scheduled plan; a `post_now` run ignores it. Consecutive posts rotate looks through the `look` stored on published receipts.
26. Captions carry at most five hashtags, Instagram's cap on posts and Reels since 2025-12-18. The prompts ask for 3 to 5, most relevant first; `hashtag_list` in `content/schemas.py` keeps the first five instead of failing the slot.
27. SVG Reel narration speaks only the validated scene's on-screen text (`narration.lines`), never extra model-written words or numbers, so contract 15 covers it. It runs in the locked `scripts/narrate.py` environment on Python 3.13. Any narration failure (model missing, environment install, synthesis, mix) leaves the Reel music-only and never skips the slot, and the caption carries "Narration: AI-generated voice." only when the voice is in the delivered audio. Beats only lengthen to fit a line; without narration every SVG, duration and cover frame is unchanged. A voice that would push the Reel past 30 s is read again faster (`narration.fitted`: at most 1.25x, at most twice; a failed faster read keeps the last good one).
28. The hook or stat headline never opens with a greeting, filler, a video preamble, "stop scrolling", a hashtag or an emoji (`content/hooks.py`, whole-word matches), and the caption's first line is one sentence under 125 characters. A stat scene's headline and the caption's first line never contain the stat's own figures (`spent_hook`), so the count-up is the reveal. All are validation errors that get the repair calls.
29. `versus` scenes compare two different things on 3 or 4 aspects and draw no source line (evergreen pairs are allowed, like steps). `myths` scenes hold 2 or 3 myth/fact pairs whose facts come from cited records: the topic step refuses an empty source selection, every fact is in the evidence, and the hook and caption never count the items unless the evidence states that number. Narration speaks each myth and its fact as two lines so the strike-through lands on "Fact". Both kinds keep icons optional (versus only, on the two column heads) and stay within 15 to 21 s without narration.
30. The end card's handle is the connected account's live username (`publishing/account.py`, read-only `INSTAGRAM_GET_USER_INFO` with `ig_user_id` "me"), never a hard-coded name. A failed lookup, an invalid username or one too wide at 40 px drops the handle line and the follow line takes its place; it never fails the slot.
31. SVG Reels run 15 to 30 s: every layout's duration has a 15 s floor (`MIN_S` in `svg_kit.py`) and narration is fitted toward 30 s (contract 27). The first second shows the subject, not only the hook: the stat visual starts at 0.4 s (`VISUAL_S`) and the first step, milestone, versus row or myth card lights at 0.7 s (`FIRST_S`); narration beats stay where they were. The owner asked for this on 2026-10-24 after 80% of views on the first 14 Reels left within three seconds.

## Creating a Reel on demand ("create one")

When Sagar says "create one" (or "post one", optionally naming a pillar), that is the per-post ask; run it without asking again:

1. Pillar: the one he named, else the pillar whose latest published slot key on the `autopilot-state` branch (`data/publication_state.json`) is oldest. Say which.
2. `gh workflow run daily-post.yml --repo Sagargupta16/instagram-autopilot --ref main -f pillar=PILLAR -f post_now=true` (add `-f dry_run=true` when he asks for a preview), then find the run with `gh run list --workflow daily-post.yml --limit 1` and `gh run watch` it.
3. A refusal (outside 04:00-20:00 UTC, two posts already today, under 180 minutes since the last) is a normal outcome: report the reason and when the next post would be allowed, never work around it.
4. On success, confirm the Reel on the account (Composio `INSTAGRAM_GET_IG_USER_MEDIA`, read-only) and report its permalink, pillar and look; the run may have posted a fallback pillar (contract 19), so report the pillar it actually used. On a failure, read the run log and report the cause; asking again starts a fresh chain within the attempt budget.

## Conventions

Type hints, pathlib, small modules, explicit contracts. Target under 200 lines per module; hard limit 300. Tests mirror source areas. No credentials in logs, state, artifacts, or commits. The existing untracked audio-download script belongs to the user; do not overwrite it.
